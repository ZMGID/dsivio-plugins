# 排名与清单

## 何时使用

作品通过比较标准与逐项判断推进，观众需要记住前项结果时读。

本页是制作决策，不声明新的作者元素；准确属性读 [制作参考](../../production/tracks.md)。不同格式可以组合。

## 1. 比较标准先于外观

写出标准、证据与争议，不把排行数字当论点。TierBoard 表示等级群组，Column 表示有名次的累积列表，TopThree 表示三项顺序揭示；普通清单不必硬套排名。

## 2. 状态与揭示分开

TierItem/ColumnItem 的 during 表示揭示阶段，结果之后持久保留；preset 项先存在，禁止同时给定时阶段。TopThreeItem 用 Instant，terminal 只绝对时间/Moment。先安排论点与出现/归位，再设置 appear-frames/move-frames。

## 3. 图像服务识别

TierItem 必须 icon，其他形态可用 label。引用真实图片或经许可生成；精确字形来自 Style font。画布同时有讲解者时留安全框，别让 stage 遮住嘴和字幕。

## 4. 音效和检查

绑定 appear-sound/move-sound 才有 .audio/events，并在 Film 明确接入；无绑定时不引用该音轨。check/plan，再看 schedule 与实际 get 成片，查重复 rank、项的持久记忆、最后停留和对白连续。

## 门禁与常见偏差

不要写 ranking:Track，也不要将声明顺序当跨轨 z-index。

最终仍执行 check → plan →（实际 paid 请求先审批）→ build --follow → get；记录 Build ID、文件与真正看过/听过的范围。未知结果先 status，不新建付费 Build 重试。

# 双人播客

## 何时使用

对话关系、反驳与反应是内容主体时读。

本页是制作决策，不声明新的作者元素；准确属性读 [制作参考](../../production/tracks.md)。不同格式可以组合。

## 1. 建立共同空间

机位必须能解释两人坐向、视线和产品位置。生成时共享有用世界与身份参考，不假装不同图自动连续；未说话者仍有反应。导入素材保留其实际声音。

## 2. 编排对话而非交替模板

Script role 保存谁说；段落随观点划分，不要求一句一 Take。Normalize 每段，再 SemanticTake→Timeline。performance 的窗口可切机位，sound 的窗口保持语义和源相位；不因画面切换就剪断话尾。

## 3. 补充证据不打断思想

media-track 的覆盖可以服务整段思想而非逐名词配图；caption-fine 用 role 样式。有实际 RegionTimeline 才启用跟踪布局，切镜不自行插值。音乐另用 audio-track 并检查遮蔽。

## 4. 视听一同验收

check/plan/build/get 后看完整交流：听者反应、递交动作、J/L-cut、字幕身份、音量主次。media tile 辅助检查机位，不能证明谈话完整。

## 门禁与常见偏差

不要推断插件有 voice-design、TTS 或自动口型修复；生成只用已发现的 gen:Video 模型。

最终仍执行 check → plan →（实际 paid 请求先审批）→ build --follow → get；记录 Build ID、文件与真正看过/听过的范围。未知结果先 status，不新建付费 Build 重试。

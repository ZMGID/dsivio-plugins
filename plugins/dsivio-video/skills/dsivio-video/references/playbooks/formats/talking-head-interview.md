# 口播与采访

## 何时使用

人物直接承载观点，或问答关系决定镜头时读。

本页是制作决策，不声明新的作者元素；准确属性读 [制作参考](../../production/tracks.md)。不同格式可以组合。

## 1. 先确定对观众的态度

台词进入 Script，分别记录提问/回答的 role、意群和揭示点。口播不是自动热情推销；采访不是只列一个答案条。留沉默、反应与转换视角的理由。

## 2. 让表演与声音各有所有者

导入有声视频，用明确选流策略 Normalize，再 language 明确的 SemanticTake。performance 调整画面框，sound 连续播放对白；media-track 的 B-roll 可以遮人而不切断说话。音频-only 主轴也可承载内容。

## 3. 字幕和答案条分工

caption-fine document={story.caption} 用对齐词锚；role 区分不同说话者。只有用户明确需要且有测量 evidence 才传 regions，不自动开启检测。interview-emoji-reveal 需实际 placeholder/icon，答案 Moment 控制 at；独立音效用 audio-track。

## 4. 验收人和文字

查嘴型、反应、对话关系、切镜动机与字幕安全区。短揭示不应挤掉阅读时间；评论贴纸要说明出处或创作身份。check/plan/build/get 后完整听声音，不以 snapshot 验收对白。

## 门禁与常见偏差

没有口播素材就先设计生成并审批预算；不编造 TTS 或声线克隆命令。

最终仍执行 check → plan →（实际 paid 请求先审批）→ build --follow → get；记录 Build ID、文件与真正看过/听过的范围。未知结果先 status，不新建付费 Build 重试。

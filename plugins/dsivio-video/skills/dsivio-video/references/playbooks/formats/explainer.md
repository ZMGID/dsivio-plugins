# 讲解与复杂图形

## 何时使用

人物或旁白说明变化关系，图形承担论证时读。

本页是制作决策，不声明新的作者元素；准确属性读 [制作参考](../../production/tracks.md)。不同格式可以组合。

## 1. 把变化关系写成可见状态

先列观众起初知道什么、每步新增什么、结尾应理解什么。真实界面证据和作者示意明确区分；不能用漂亮图板冒充实测截图。

## 2. 分清时间主轴

已有旁白 Normalize 成音频媒体，SemanticTake 提供词锚，再 Timeline；图形从语义事件开始、按独立运动时长展开。纯动画不用虚构 Script/ASR，可 Timeline 零 Take + 正 end。

## 3. 保持对象与层级

typography 承担准确标注，media-track 展示证据，deck-track 组织卡片状态；performance 的播放独立于其视框。Film 只显式接终端 .track/.visual/.audio，Recipe 的 stack-order 决定跨轨关系。

## 4. 代表片段迭代

先制作最复杂的一次对象变化。snapshot 查关键帧及直接 seek，get 影片查运动和声音；check/plan/build 的可编辑输出交接给下一轮。纯本地示例见 production/examples，费用无需捏造审批。

## 门禁与常见偏差

先保证阅读时间和因果可见，再加 overlay，不能用粒子替代解释。

最终仍执行 check → plan →（实际 paid 请求先审批）→ build --follow → get；记录 Build ID、文件与真正看过/听过的范围。未知结果先 status，不新建付费 Build 重试。

# 用最便宜的有效小样回答问题

决定生成规模、参数或重做时读。先保持用户许可与不确定性规则，不能以“只是测试”绕过付费审批。

## 先减少付费问题数量

1. 写清当前未知：身份？产品接触？动作？对白？镜头？不为了找感觉无目的批量抽取。
2. 优先用用户素材和已接受 Output 验证编排；修字幕/布局不重生表演。
3. 选目录支持且报价确实更低的测试 settings：尽可能短的有效 duration、够观察问题的 resolution/size/quality、count=1；不要默认最低清晰度在每个渠道一定最便宜。
4. 声音是验收重点时保留声音测试；不是重点且模型支持时才考虑关闭 audio。关闭声音不是确定的折扣。
5. 只 Target 准备好的资产/片段，不提前把全工程付费依赖一起触发。

## 给 plan 一个真实预算决策

| 已知情况 | 动作 |
|---|---|
| 有可靠价格和剩余预算 | 报告请求数、参数、依据和上限，确认许可覆盖 |
| 目录没有价格 | 明确“无法据此给出精确费用”；取得有限工作范围/预算授权后再 build |
| 上游结果未有，后续请求 waiting | 展示依赖与未知，别把等待项算成已完整校验的报价 |
| 请求超出工作、金额或执行账号许可 | 停在付费门禁，重新决策 |
| 退出码 5、超时或无回执中断 | 查原任务，不重抽，不用新 Build 当重试 |

## 接受素材后显式锁住

将已接受素材通过 build-record/satisfy 写进 Run。每轮 check/plan，核对剩余请求确实缩小；失败 Build 已完成 Output 也能保留。先看小样再扩大制作，不用更高 quality 遮住错误动作或身份。

小样检验通过只证明该素材适用，不证明后续所有随机生成会同样成功。保留实际输出和回执，让每笔付费都能对应一个制作判断。
